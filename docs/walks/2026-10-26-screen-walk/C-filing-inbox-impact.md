# C: Filing Requests, Inbox and Impact

## Covered

- **New Request composer** (centred dialog), opened from the sidebar pencil, the strip's "New Request" button, the + in the Open group header, the C key (on `/`, `/inbox`, `/impact`) and `/intake`'s Create Request. Every picker opened and closed with Escape: Project, Labels, Priority, Reviewers, Add link, Metric (search, create offer), Audience, Platform, Measurement window (presets and Custom date range calendar), plus No measurable impact with its reason. Validation: empty submit, title only, 250-character title, 12,000-character description. Escape / X with unsaved text, reopen, X and Esc while the AI check runs, the review step, Create, toast and where you land (list → new row focused; `/intake` → Request page). Offline at the review step and at Create. Sizes: 1440 light and dark (full), 390×844 dark, 390×500 light (keyboard stand-in), 768 light, 1024 dark; axe and overflow at 1440/1024/768/390 in both themes.
- **`/intake`**: the launcher page (empty-state + Create Request), the first-run guided composer (as `fresh` in `freshOrg`), draft recovery (fill, reload: the composer reopens by itself with title, description and Priority kept; Escape returns focus to Create Request), creating from `/intake`, offline, loading. Note: `/intake` is no longer a full-page form; `intake-form.tsx` is the composer itself, so its spacing is judged inside the dialog. Its only arbitrary Tailwind value is `max-w-[62ch]` on the first-run hints (C27).
- **`/inbox`**: full (PM, 4 unread For your information, Needs you appearing and clearing as walker B raised a concern), empty (as `empty`), opening an item (preview beside the list on desktop, full Request page on phone), J/K/Home/End/arrow keys, Enter, Escape back to the row, the read toggle, Mark all read, long names, offline open / mark read / navigation, throttled loading (client and hard load), 1440/1024/768/390 in both themes. Read states I changed were put back to the seeded state afterwards. Inbox delivery settings live in Settings → Profile (`settings/profile/delivery-form.tsx`), not walked (settings walker).
- **`/impact`**: My work (PM), teammate lists, Outcome report (Month / Quarter / Year, period picker, earlier quarter with nothing released, Print button present, Quarter note editor open + Escape), empty as `empty`, offline, loading, 1440/1024/768/390 in both themes.
- **Not walked: the metric chart.** It only draws on Outcome report "Totals" lines that have a recorded result, and the seed has no Request closed with a result (my own Request cannot be picked up without a current value, and recording a result needs the due date to pass). So "Dark mode: chart labels are hard to read" could not be checked on screen. From the code (`components/impact/metric-chart.tsx`), the chart has no axis, no values on the bars and no tooltips; the only text is a 12px muted legend. That needs a re-check once a closed Request with a result exists.
- Not a bug, recorded as found: Escape or X with unsaved text closes the composer without asking. The draft is kept for that browser tab (sessionStorage), so reopening restores it, but a new tab starts empty. X / Esc during the AI check cancel the check and return to the form with the draft (the recorded 2026-10-21 decision).
- Ignored as dev-only: one 404 on a dev chunk (`first-run-invite-form`) on `/intake` as `fresh`, and "Failed to fetch RSC payload" console lines while offline.
