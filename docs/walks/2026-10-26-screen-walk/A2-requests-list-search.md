# A2: Requests list (`/`), search and first run

## Covered
- **Requests list, full workspace** (`pm` / fullOrg): 1440 light and dark, 1024 light, 768 light, 390 dark. All 7 status pills; group headers (collapse with mouse and the Left/Right keys, counts, the + on the Open group); every row column (priority glyph, code, status circle, labels with +N, Project chip with the long Project name, assignee, date); row hover; selection with X and the selection bar; keyboard grid (arrows, J/K, Home/End, Enter, Space for the preview, F for the filter); row right-click menu and its Status submenu; Request preview panel; list summary panel (the panel button top right); "N more" status menu at 768/390; filter popover; display options; the title filter; pagination; the Project page with the long name and "No Project".
- **Saved views**: Save view dialog (empty name, long name, offline), saved view dropdown, "Filters changed" state, Rename, Delete confirmation. Done with my own "[A2] …" views; the one left in place is "[A2] Renamed view".
- **Search**: the sidebar search pane at 1440 light and dark, 1024, 390 dark: typing, results, arrow keys, the facets, no results, a 300-character query, clearing, recent searches, Escape twice, the `/` shortcut. On phone: the Filters bottom sheet and the Result preview bottom sheet.
- **Empty states** (`empty` / emptyOrg): the list, each status pill by URL, No Project, search with no results.
- **First run** (`fresh` / freshOrg): steps 1 to 5 forward at 1440 light, backward at 390 dark, step 5 at 1440 dark; filed "[A2] Field notes vanish after reconnecting" through the guide (composer, review, create), then the "Your first Request is filed" card and "See the steps again" at 1440 light and 390 dark.
- **Loading**: throttled client navigation to `/` (skeleton compared with the loaded page). **Offline**: status pills, filter, Save view, Pick up, priority change (on my own Request in freshOrg).
- **Not walked**: `/onboarding` (it redirects to `/` for `fresh`, whose onboarding is already done), so the onboarding-page items in page-quality.md were not checked. Guest/Viewer read-only pills (no such user in my group). A throttled full reload (the screenshots only caught the old page). Motion timing (springs) was not measured.
