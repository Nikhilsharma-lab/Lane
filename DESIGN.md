# Lane product design: Arc components and one theme file

Arc UI supplies product components, APIs, interactions and motion. One theme file, `src/styles/theme.css`, supplies every visual value: colours, fonts, corners, shadows, sizes and motion, in light and dark (Nikhil, 2026-10-22, spec #87). Use official Arc components and licensed Pro source, connected to the theme through `src/styles/theme-bridge.css`. Keep Geist and existing product composition. On 2026-10-07, Nikhil explicitly approved Linear as the interaction and navigation reference for Requests, Request detail and Projects. This does not introduce another visual library or expand the product scope. Do not consult retired themes.

Marketing is a separate local project, not part of this repository. The old `marketing/` repository was removed on 2026-10-15.

**Visual system (current, 2026-10-22):** `src/styles/theme.css` is the single source of Lane's look. Its top half is tweakcn's export, pasted verbatim and never hand-edited; its bottom half, **Lane additions**, holds what tweakcn has no slot for (status, Project and avatar colours, extra text levels, see-through lines, exact corners, menu shadows, type scale, sizes, motion). `src/styles/theme-bridge.css` only renames Arc's and Lane's existing names onto the theme's and holds no values. `src/app/globals.css` loads the theme, Arc's `foundation.css` in a lower cascade layer, and the bridge. The values are the ones Lane painted under the 2026-10-13 Supabase decision, which this replaces; they still miss WCAG AA in places by Nikhil's decision. Product CSS writes no design literals; it reads theme or bridge names, and `pnpm design:check` enforces this. To change the look, re-paste a tweakcn export: see `docs/design-system/theme-file.md`.

History: on 2026-10-08 Nikhil reviewed a Geist neutral + blue preview and then a Linear-style density review (values captured from Linear); on 2026-10-09 that review went to production; on 2026-10-10, under the accepted MVP launch plan (decision 8.7), the captured values were replaced by Lane-authored tokens (`lane-primitives.css`, accent blue-violet from 2026-10-11); on 2026-10-13 those were replaced by Supabase's tokens and the file was deleted; on 2026-10-22 the Supabase token layers (`supabase-tokens.css`, `lane-arc-theme.css`) were replaced by the one theme file and deleted. The 44px rows, 13px type and blue-violet accent no longer apply.

## Authoritative sources

- [Arc documentation](https://uiarc.dev/docs/introduction), [theming](https://uiarc.dev/docs/theming), and [AI/MCP](https://uiarc.dev/docs/ai).
- Official installed skill: `.claude/skills/arc/SKILL.md`; licensed workflows: `.claude/skills/arc-pro/SKILL.md`.
- Source: `src/components/arc/`. Arc's `foundation.css` defines the token names its components read; it loads in its own cascade layer below the theme, and the theme or bridge defines every one of those names, so `src/styles/theme.css` is the single source of visual values. Geist and Geist Mono load in `src/lib/fonts.ts` under the family names the theme's font slots use. Light and dark follow the `.dark` class (and `data-theme`) on `<html>`; Arc's accent presets (`data-accent`) are not set in production. The accent is the theme's green. Keep success, warning and danger semantic; they and the Project colours live in Lane additions so a brand change never moves them.
- `src/app/globals.css` loads the theme, Arc's foundation and the bridge, and sets base type from theme names. It must not define a second palette, font system, theme or component reset. No per-surface token overrides; never restore the retired Supabase token files.
- Registry IDs and adaptations: `docs/design-system/arc-sources.md`. `components.json` uses Arc registries only. The shadcn installer is a transport dependency; its Radix-compatible configuration prevents it from rewriting Arc's APIs.

## Implementation

Read actual Arc source and documented props before use. Install existing items where suitable; compose Lane's existing behavior around them. Do not copy demo data, pretend callbacks work, or introduce demo features. Record a functional gap and any necessary adaptation. Prefer stock Lucide icons with Arc's sizing and stroke conventions. Product-specific shapes, semantic markup and state controllers are application code, not a competing design library.

Clerk owns authentication, organizations and invitations. Retain its working flows and apply Arc through its supported appearance API. Server identity, permissions, saved data, AI review, draft recovery and private uploads must survive the migration. `REQUIREMENTS.md` is the product behavior authority. This visual migration adds no routes, tables, AI calls or cron jobs.

## Verification

Verify production components in the running app (Storybook was removed on 2026-10-21): light and dark modes, 390/768/1024/1440 widths, loading/empty/error/success, long content, keyboard operation, focus return and reduced motion. Keyboard focus uses Arc's shared `:focus-visible` outline (`--focus-outline`); pointer focus draws no ring, and fills mark hover, open menus and selection. Keep semantic labels, headings and live regions; correct a demonstrated contrast issue with an existing Arc semantic token and document it. Run TypeScript, lint, relevant behavioral tests and the production build. Local verification is not deployed/provider verification.
